Here: external Port programs, not linked-in drivers.

03:45-04:05

  • A Port is a BEAM object connecting one BEAM process to an external resource.
  • In this talk, that resource is a separate executable reached through byte streams.
  • The process attached to the Port is its connected process and receives Port messages.
  • Linked-in Port drivers are different: they run inside the VM and do not provide this crash boundary.

Open a Port

port =
  Port.open({:spawn_executable, executable()}, [
    :binary,
    :exit_status,
    packet: 4,
    args: ["--port"]
  ])

The calling process becomes the Port's connected process.

04:05-04:35

  • Highlight spawn_executable, then the options.
  • {:spawn_executable, path}: runs that file directly, without a shell or a PATH search (use System.find_executable/1). {:spawn, command} splits on spaces, may invoke the shell, and starts a linked-in driver if one has that name.
  • :binary: data arrives as binaries, not lists of bytes.
  • :exit_status: when the program exits, the owner gets {port, {:exit_status, status}}. A signal shows as 128 + signal, so a segfault is 139.
  • packet: 4: the BEAM adds a 4-byte big-endian length to every command and strips it from replies, so each {:data, data} message is one complete packet.
  • args: each list element becomes one argv entry, with no shell expansion. Only valid with spawn_executable.
  • Other useful options, if asked:
    • cd: dir: working directory for the program.
    • env: [{~c"NAME", ~c"value"}]: extends the program's environment.
    • line: n: line-based framing instead of packets; messages are {:eol, line} or {:noeol, chunk}.
    • :eof: the Port stays open at end of file and sends {port, :eof} instead of closing.
    • :stderr_to_stdout: merges stderr into the protocol stream. Avoid with packet framing.
    • :nouse_stdio: protocol on fds 3 and 4, leaving stdout free.
    • busy_limits_port: {low, high}: when the Port's output queue counts as busy. Defaults 4096 and 8192 bytes.
